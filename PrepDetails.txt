8. ref, out, and in Parameters - 

ref - i want method to modify my original variable 

out - method, you give me value through this variable 

in - method , you can read my original variable , but dont modify it

Think about it like this - Imagine you're giving your employee access to a document.

Normal parameter- Here's a copy of my document.
ref - Here's my actual document. You can modify it
out - "I don't have this document yet. You create/fill it and give it back to me.

in - Here's my actual document. You can read it, but don't modify it


- brief - 

ref → method can modify the original variable

out → method provides a value through the variable

in → method can read the original variable but cannot modify it

9. string vs stringbuilder - 

string  - string is sequence of character that used to store text 
    - string is immutable 
    - once string object is created it is value cannot be change 
    - string name = "Dhananjay";
    - name = "Rahul";
    - it look like we changed string but internally 
    C# create new string object


    - Immutable 
    - Good for normal text 
    - Simple to use 
    - create new string when modified
    - good for small/simple operation  
    
stringbuilder - stringbuilder is used to create and modify string efficiently , especially when we need many changes 
    - Mutable 
    - Good for repeted modifcaiton 
    - slighly more complex 
    - modifies it is internal buffer 
    - good for many string operations

Why is StringBuilder faster than string when performing many modifications?

Because StringBuilder modifies its internal buffer instead of creating a new string object for every modification.

Use StringBuilder when you're doing many repeated modifications, such as building a large string inside a loop.

string
